# Self-Hosted Stack

**Backlog:** BL-102  
**Status:** BL-106 topology deployed and verified. SupportPlane now uses Zammad sandbox read (BL-107), local Ollama/Gemma metadata (BL-108/BL-121), OpenBao sandbox credential resolution (BL-109), NATS JetStream bridge (BL-110), sandbox internal-note writeback with MinIO/Mailpit evidence (BL-111/112/113), sandbox egress/writeback gates (BL-115), and a local-only observability baseline (BL-114).

## Current Truth

SupportPlane is currently a local/mock MVP with cluster topology deployed. API runs on `localhost:4110` (local) and `localhost:4210` (cluster), Web on `localhost:3200` (local) and `localhost:3300` (cluster), PostgreSQL on `localhost:5434` (local) and in-cluster (cluster). The local Kubernetes cluster `supportplane-local` now runs:
- SupportPlane API/Web/Worker in `supportplane-app`
- PostgreSQL in `supportplane-data`
- OpenBao in `supportplane-integrations`
- NATS JetStream in `supportplane-integrations`
- Mailpit in `supportplane-integrations`
- MinIO in `supportplane-data`
- Zammad in `supportplane-integrations` (with separate PostgreSQL and Redis)
- Observability namespace with OpenTelemetry Collector, Prometheus, Grafana, and Loki in `supportplane-observability`
- Ollama is host-controlled (not in-cluster)

Zammad read is real against the local sandbox. AI is local Ollama/Gemma with fallback metadata and no cloud calls. Sandbox writeback is local internal-note only after approval and policy gates. Credential references resolve server-side through local OpenBao only. Outbox state remains PostgreSQL canonical with a local NATS JetStream bridge. Observability is local-only: correlated app logs, Prometheus metrics, Grafana datasource provisioning, OpenTelemetry Collector, and Loki deployment without a committed log shipper. None of this is production-grade.

## Target Direction

SupportPlane should evolve into a local self-hosted Kubernetes sandbox running on Podman. The sandbox should contain the services needed to prove one credible end-to-end workflow:

```text
Zammad sandbox -> SupportPlane lookup -> Ollama draft/summary -> human approval
-> delivery policy/outbox -> NATS JetStream worker -> OpenBao credential lookup
-> sandbox-only Zammad internal note -> Mailpit local email capture
-> MinIO evidence artifact -> PostgreSQL canonical state -> observability
```

This sandbox is local development infrastructure, not production infrastructure.

## Phase Summary

- **Phase 1:** SupportPlane API/Web/Worker and PostgreSQL in a local Kubernetes-on-Podman cluster.
- **Phase 2:** Self-hosted service topology: Zammad, OpenBao, NATS JetStream, Mailpit, MinIO, and Ollama placement decision.
- **Phase 3-10:** Real read connector, local AI, credential resolver, durable worker, sandbox-only writeback, evidence artifacts, local email, and local observability.
- **Later/future-only:** PBX/CTI, endpoint diagnostics, operator companion, screen monitoring/OCR, remote-support context.
